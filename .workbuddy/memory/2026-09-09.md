### 用户反馈修正（同日）
- 用户明确否决了顶栏 "Dynamsoft Ready" 状态胶囊：与设置按钮功能重复、且用户没要求加。已删除（HTML/JS/CSS/README 同步清理），
  激活状态只在 Settings 弹窗内的 badge 显示。教训：不要主动添加用户未要求的 UI 元素；状态展示保持单一出口。
- 注意：index.html 已被用户的可视化编辑器加了 `data-page-node-id` 属性（107 处），后续编辑必须保留这些属性。
- 修正后复测：胶囊从 DOM 移除、QR 解码正常、设置弹窗 badge 正常、无 page error。
- 用户再次否决"页面加载自动激活 license"：自动激活会用内置 key 抢先初始化，导致用户填自己的 key 点 Activate 时被
  `isSDKReady` 短路，且按钮 disabled，等于无法换 license。已改为纯手动：DOMContentLoaded 只回填 localStorage 的 key + 刷新 badge。
  关键修复点：① 用 `activatedLicenseKey` 比对，同 key 才跳过，换 key 允许重新激活；② 成功后不再 disabled 按钮；
  ③ 输入框 input 事件把按钮恢复成 "Activate"；④ loadWasm / createInstance 只执行一次（wasmLoaded、cvr 判空）。
  教训：Dynamsoft 这类需要 license 的 SDK，激活时机必须交给用户，不要在启动时自作主张初始化。
